## Section 1 — Purpose

This document defines the criteria for when an aggregated pressure pattern is stable enough to be reviewed by the operator.

The purpose is review-readiness only — a signal that a pattern has persisted long enough, across enough runs, to warrant human inspection. It is not authorization for action. It is not value inference. It is not behavior change.

Readiness means: *this pattern has been observed with enough consistency that an operator should look at it.*

---

## Section 2 — Non-Meaning Rule

A stable pressure pattern is NOT a value.

A pressure pattern that meets stability criteria is a candidate for operator review. It carries no meaning about what WESLR "wants," "prefers," or "tends toward." It is a behavioral signal — nothing more.

The pattern:
- has been observed multiple times
- has appeared across multiple independent runs
- has not been disqualified by noise, synthetic input, or reset contamination

What it is NOT:
- A declared value
- An inferred preference
- An authorization for behavior change
- A proposal trigger

The word "stable" in this document refers to statistical persistence, not moral or operational stability. It does not mean the pattern is "good," "right," or "desired."

---

## Section 3 — Required Inputs

A stability assessment requires the following inputs:

| Input | Source | Purpose |
|-------|--------|---------|
| `pressure_summary` | `pressure_aggregation.py` output | Grouped pressure indicators with persistence scores |
| `total_runs` | `pressure_aggregation.py` output | Number of observation runs included |
| `temporal_span` | `pressure_summary[].temporal_span` | Distance between first and last occurrence |
| `persistence_score` | `pressure_summary[].persistence_score` | Deterministic persistence indicator [0.0–1.0] |
| `run_diversity` | `pressure_summary[].run_diversity` | Number of runs where the pattern appears |
| `occurrences` | `pressure_summary[].occurrences` | Total count across all runs |
| Source signal provenance | Signal log records | Chain from raw observation to pressure classification must be traceable |

All inputs must be present and non-null. If any required input is missing, the pattern is not review-ready.

---

## Section 4 — Stability Gates

A pressure pattern is **review-ready** only if ALL of the following gates are satisfied:

| Gate | Condition | Rationale |
|------|-----------|-----------|
| G1 — Multi-run presence | Pattern appears in at least 2 distinct runs | Single-run patterns are insufficient |
| G2 — Run diversity | `run_diversity >= 2` | Pattern must appear across independent observation contexts |
| G3 — Temporal spread | `temporal_span >= 1` (runs apart) | Pattern must not be confined to adjacent runs |
| G4 — Persistence threshold | `persistence_score >= 0.60` | Sufficient consistency across frequency, diversity, and time |
| G5 — Minimum observation window | `total_runs >= 3` | Enough runs to establish cross-session persistence |
| G6 — Source traceability | Raw signal provenance chain is documented and available | Unverifiable patterns are invalid |

If any gate fails, the pattern is **not** review-ready.

---

## Section 5 — Minimum V1 Thresholds

These thresholds define the minimum conditions for review-readiness in V1:

| Criterion | Threshold | Notes |
|-----------|-----------|-------|
| `total_runs` | >= 3 | Minimum observation window |
| `run_diversity` | >= 2 | Pattern must appear in at least 2 runs |
| `persistence_score` | >= 0.60 | Clamped [0.0, 1.0]; score < 0.60 is below review threshold |
| `temporal_span` | >= 1.0 | Pattern spans at least 1 run gap between first and last occurrence |
| Source provenance | Traceable | Raw signals must be retrievable and linked |

These are conservative thresholds. Patterns that do not meet all five are not ready for operator review under this doctrine.

The thresholds are NOT:
- Rankings of pressure categories
- Authorization for behavior change
- Indicators of pattern importance

---

## Section 6 — Disqualifiers

A pressure pattern is **NOT** review-ready if any of the following is true:

| Disqualifier | Condition | Rationale |
|--------------|-----------|-----------|
| D1 — Single-run only | Pattern appears in exactly 1 run | Insufficient for cross-time validation |
| D2 — Missing provenance | Source signals are not traceable | Unverifiable patterns cannot be reviewed |
| D3 — Synthetic injection | Pattern generated by artificial test inputs not from organic observation | Observation environment constraint SP6 |
| D4 — Reset contamination | Pattern result is contaminated by observation environment reset (IG1-IG5) | Cross-run state linkage violates isolation |
| D5 — Noise-only basis | Pattern derived exclusively from malformed, adversarial, or off-topic signals | No meaningful behavioral signal present |
| D6 — Threshold not met | One or more stability gates (G1–G6) failed | Default state: not ready |

Disqualification is the default state. Patterns must affirmatively pass all gates.

---

## Section 7 — Review Output

When a pattern passes all stability gates, the appropriate output is:

> "This pressure pattern is stable enough for operator review."

This output is appropriate because it accurately describes the pattern's cross-run persistence without implying value, preference, or authorization.

The following language is **explicitly prohibited** in any output derived from stability criteria:

| Prohibited phrase | Reason |
|-------------------|--------|
| "value detected" | Implies value inference — not authorized |
| "preference detected" | Implies preference — not authorized |
| "WESLR wants" | Anthropomorphism — prohibited by doctrine |
| "WESLR should change" | Authorization for behavior change — not granted |
| "pressure pattern is active" | Ambiguous; use "stable enough for review" instead |
| "pattern indicates behavior" | Behavior inference — not authorized |

The stability criteria output is a description of observation history, not an interpretation of meaning.

---

## Section 8 — Operator Role

When a pressure pattern is identified as review-ready, the operator may:

- **Inspect** — review the pattern's signal provenance, confidence scores, and temporal characteristics
- **Reject** — determine that the pattern is noise, test artifact, or otherwise not meaningful
- **Continue observing** — decide that insufficient time has passed to draw conclusions
- **Request more data** — ask for additional observation runs before forming a judgment

The operator may **NOT**:
- Treat review-readiness as authorization for behavior change
- Use a passing stability assessment as proof of value or preference
- Implement proposals based solely on review-readiness without separate governance
- Infer that persistence implies desirability

Review-readiness is a signal for inspection, not a judgment of correctness.

---

## Section 9 — Relationship to Governance

Stability criteria operate before the proposal layer in the signal-to-behavior pipeline.

```
Layer 1: Signal Collection
Layer 2: Pattern Detection
Layer 3: Pressure Classification
Layer 4: Aggregation
Layer 5: Stability Assessment ← This layer (review-readiness only)
Layer 6: Operator Review
Layer 7: Proposal (future)
Layer 8: Behavior Change Authorization (future)
```

Stability criteria do not create proposals. They do not trigger governance events. They do not modify behavior or route signals differently.

A review-ready pattern means: *the operator should look at this.* It does not mean: *something should be done.*
