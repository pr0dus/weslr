WESLR Status

Current implementation status, public visibility, and availability

Overview

WESLR contains implemented and reviewed systems in the codebase. Public access is still controlled, and not every implemented subsystem is exposed as a public product.

Implemented and Reviewed

WESLR contains implemented and reviewed code where the source/docs/tests show the completed workflow: design → implementation → review → tests → commit.

Examples: Thread management, entity extraction, topic tracking, evidence RAG, capability discovery, request intelligence, operator feedback logging, behavior phases B1-B11.

Publicly Visible Now

Some subsystems are exposed as public interfaces with controlled access. These include the public API, limited pilot access, and select documentation pages.

Status: Controlled access, invite-only pilot, documentation-only exposure.

Protected/Internal

Many implemented features are internal-only due to governance, safety, or operational boundaries. These include operator approval workflows, red-zone flags, secret cleanup, and protected runtime tooling.

Examples: Controlled self-modification, operator feedback logging, write control presets, M-layer audit helpers.

Not Publicly Live Yet

Some capabilities exist in the codebase but are not yet exposed as public interfaces. These require additional work before public access can be granted.

Examples: Server-side STT/TTS, external person timelines, persistent human memory across sessions.

Not Claimed

WESLR does not claim AGI, consciousness, official benchmark proof, certification, or production guarantee. It is a local operator-facing research system.

Explicitly not claimed: Production-grade software, certified AI, conscious agents, autonomous economic agents, public marketplace.

Key Distinction

Implemented in WESLR codebase ≠ publicly open product

Implemented in WESLR codebase ≠ open public chat

Implemented in WESLR codebase ≠ live marketplace

Implemented in WESLR codebase ≠ unrestricted autonomous runtime

Implementation Status Categories

Implemented and Reviewed

  • Thread management (thread_tracker.py)
  • Entity extraction (entity_extractor.py)
  • Topic tracking (interpretation.py::_track_topic)
  • Entity co-occurrence (entity_cooccurrence.json)
  • Evidence RAG (evidence_pipeline.py)
  • Capability discovery (capability_discovery/)
  • Request intelligence (request_intelligence/)
  • Artifact scoring (opportunity/sellability)
  • Operator feedback logging (log_operator_feedback)
  • Behavior phases B1-B11 (dialogue.py)

Protected/Internal Only

  • Controlled self-modification (requires operator approval)
  • Write control presets (normal, observe, topic_only, etc.)
  • Dry-run modes (interpret_human_turn(dry_run=True))
  • Operator feedback statistics (read-only inspection)
  • M-layer audit helpers (caller scanning)
  • Red-zone flags (operator safety controls)
  • Secrets cleanup (runtime safety)

Not Publicly Live Yet

  • Server-side STT (scaffolded, optional binaries)
  • Server-side TTS (not implemented, browser only)
  • Human long-term memory (no persistent memory across sessions)
  • External person timelines (WESLR-only entity tracking)
  • Real-time voice assistant (only shim + browser STT/TTS)
  • Wake word detection (not implemented)
  • VAD (voice activity detection, not implemented)

Public Safety Boundaries

Forbidden Claims

  • Autonomous coding (requires operator approval loop)
  • "Remembers everything" (no persistent human memory store)
  • Predictions, forecasts, "knows what will happen"
  • Sells products, generates revenue
  • Real-time voice assistant (only browser STT/TTS)
  • Feelings, emotions, consciousness, self-awareness
  • Production guarantee, certification, official benchmark proof

Permitted Language

  • "Local agent research sandbox"
  • "Discovers recurring operator pain, turns into inspectable artifacts"
  • "Thread-based conversation management"
  • "Dual scoring system (internal + opportunity/sellability)"
  • "Artifact clustering into opportunity-themed packs"
  • "Operator feedback logging (manual trigger)"
  • "Read-only inspection modes"
