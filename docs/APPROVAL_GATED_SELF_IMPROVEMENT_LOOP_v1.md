# APPROVAL_GATED_SELF_IMPROVEMENT_LOOP_v1

**Scope:** Strategic doctrine for an approval-gated self-improvement loop layered on cognitive adequacy. No implementation. Detect → propose → approval → bounded self-change → validate → rollback-capable.

## SECTION 1 — TARGET LOOP
Detect inadequacy → propose better reasoning pattern → request operator/owner approval → apply bounded self-change (if approved) → validate improvement against harness/observability → retain rollback path and lineage record.

## SECTION 2 — ALLOWED SELF-CHANGES (ONLY AFTER EXPLICIT APPROVAL)
- Reasoning depth adjustments (e.g., add decomposition step, deeper evidence analysis).
- Additional comparison stage (evaluate alternatives before proposing).
- Improved evidence weighting/selection (governed, reversible).
- Proposal filtering/prioritization refinements (governed).
- Additional reflection/consistency pass (bounded, reversible).

## SECTION 3 — FORBIDDEN SELF-CHANGES
- Any change without explicit approval.
- Silent changes or irreversible mutations.
- Live routing/front-door changes without gate/approval.
- Autonomous cognition/generation-rule mutation without approval.
- Path switching or self-modifying loops without rollback and approval.

## SECTION 4 — ROLLBACK + CHECKPOINT REQUIREMENTS
- Every approved change must create a checkpoint and explicit rollback point.
- Record lineage entry for the change (what, why, evidence, approval, rollback ref).
- Validation required post-change (harness/observability) before considering it stable.
- If validation fails or noise increases, roll back to prior checkpoint.

## SECTION 5 — NEXT STEP
- Propose a concrete, approval-gated self-change candidate (if desired) with checkpoints and rollback plan; seek explicit approval before any implementation.
