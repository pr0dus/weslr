# DESIGN_ARC_SYNTHETIC_3_STEP_PILOT_RUNNER_V1

## Objective
Design a **diagnostic‑only runner** for the ARC synthetic 3‑step pilot. It consumes the 20 task packets generated by `generate_3_step_pilot_tasks()` (see `arc_synthetic_3_step_task_schema.py`) and produces structured trace metadata. The runner never executes primitives, makes external calls, or emits final‑answer data.

---

### 1. Runner inputs
| Name | Type | Description |
|------|------|-------------|
| `tasks` | `List[Dict]` | The 20 diagnostic task dictionaries produced by the packet generator. |
| `trace_collector` *(optional)* | `Callable[[Dict], None]` | In‑process function that stores a trace entry; used only for internal aggregation. |

*No file I/O, model inference, or network access is performed.*

---

### 2. Runner outputs (internal only)
The runner returns a single **report dictionary**:
```json
{
  "overall_metrics": {
    "exact": int,
    "partial": int,
    "unsupported": int,
    "failed": int,
    "represented_candidates": int
  },
  "task_reports": [
    {
      "task_id": "F001_1",
      "family_id": "F001",
      "result": "exact|partial|unsupported|failed",
      "failure_step": null | 1 | 2 | 3,
      "failure_reason": null | "string",
      "trace_summaries": {
        "step_1": "summary",
        "step_2": "summary",
        "step_3": "summary"
      },
      "carried_parameters_by_edge": {"1-2": [], "2-3": []},
      "dropped_parameters_by_edge": {"1-2": [], "2-3": []},
      "sequence_visibility_reason": "string",
      "leakage_flags": {
        "arc_agi_participation_claim": false,
        "leaderboard_claim": false,
        "hidden_test_use": false,
        "public_claim": false,
        "final_answer_wiring": false,
        "weslr_persistence": false,
        "external_calls": false,
        "provider_model_calls": false,
        "runtime_chat_wiring": false
      }
    }
    // … one entry per task
  ]
}
```
All fields are **diagnostic**; no raw grids or images are stored.

---

### 3. Expected metrics (derived from the pilot)
| Metric | Definition |
|--------|------------|
| `exact` | All three trace requirements satisfied, no failure detected. |
| `partial` | Some trace requirements satisfied, at least one missing. |
| `unsupported` | Primitive sequence contains an unknown primitive (should be 0). |
| `failed` | Task flagged as failed – missing trace or explicit failure category. |
| `represented_candidates` | Number of distinct `family_id` values present (must be 8). |

---

### 4. Trace structure per task
* **Step 1** – Export summary (`step_1_exports`).
* **Step 2** – Import (`step_2_imports`) and Export (`step_2_exports`).
* **Step 3** – Import summary (`step_3_imports`).

For each edge (1→2, 2→3) the runner records:
* `carried_parameters_by_edge` – parameters that flow from one step to the next.
* `dropped_parameters_by_edge` – exported parameters not consumed downstream.

All entries are simple strings or lists; no heavy data is kept.

---

### 5. Failure categories (populated in `failure_reason`)
- `rotation_out_of_bounds`
- `object_missing`
- `count_mismatch`
- `alignment_error`
- `parameter_drift`
- `unsupported_primitive`
- `missing_trace_requirement`

`failure_step` indicates the step (1‑3) where the first problem appears.

---

### 6. Preservation of existing baselines
* The runner **does not modify** any 2‑step or single‑step code.
* Baseline statistics (`77 / 3 / 0 / 0` for 2‑step 80, `39 / 1 / 0 / 0` for 2‑step 40, `114 / 6 / 0 / 0` for single‑step) remain untouched.
* No files are written outside of this markdown design document.

---

### 7. Leakage prevention
* All `leakage_flags` are hard‑coded to `false` and asserted before output.
* No shortcuts (`expected_test_output`, `task_id_shortcut`, `generator_note_shortcut`) are allowed – they are absent from the input packets.
* The report is **internal only**: returned to the caller and optionally saved locally for review; never sent to public APIs, leaderboards, or ARC‑AGI claim surfaces.

---
