### A. Phase 1A Objective

Build the smallest viable loop to prove the self-improvement workflow:

> **A human can see a problem → Weslr proposes a fix → Human approves/denies → No code applied yet**

**Success criteria:**
1. Weslr records an observation (e.g., "repeated fallback in concept explanation")
2. Weslr creates a bounded proposal from that observation
3. Human can list pending proposals
4. Human can approve or deny a proposal
5. All state is stored safely, no code is modified

### E. Approval Workflow (Phase 1A)

**Workflow:**
```
1. Record observation → stored in self_improvement_observations.json
2. Create proposal from observation → stored in self_improvement_proposals.json
3. Proposal status = "proposed"
4. Human reviews proposal
5. Human approves or denies:
   - approve → status = "approved", record in approval_log
   - deny → status = "rejected", record in approval_log
6. Proposal remains pending (no code applied yet)
```

**Safety rules:**
- Protected files automatically denied in Phase 1A
- Approval logged before status change
- No code modified in Phase 1A

### G. Rollback-Safe Expansion Path

#### Phase 1B — Testing Layer
**Goal:** Add test execution before applying changes

**New files:**
- `self_improvement_tests.py`

**Changes to proposal schema:**
```json
{
  "id": "prop-1774547200",
  // ... existing fields ...
  "tests": [
    {
      "prompt": "Explain photosynthesis",
      "expected_type": "concept_explanation",
      "expected_contains": ["sunlight", "chlorophyll"]
    }
  ]
}
```

**New workflow:**
1. Proposal created
2. Tests run (non-destructive)
3. If tests pass → proposal.status = "approved"
4. If tests fail → proposal.status = "needs_revision"

---

#### Phase 1C — Apply Layer
**Goal:** Apply approved changes safely

**New files:**
- `self_improvement_apply.py` (wraps `self_mod_applier.py`)

**Changes to approval workflow:**
1. Approval recorded
2. Apply command executed (uses `self_mod_applier.apply_modification`)
3. Proposal.status = "applied"
4. Checkpoint created, modification logged

---

#### Phase 1D — Rollback Layer
**Goal:** Support rollback of applied changes

**Changes to proposal schema:**
```json
{
  "id": "prop-1774547200",
  // ... existing fields ...
  "rollback_command": "git checkout HEAD -- dialogue.py",
  "rollback_executed_at": null,
  "rollback_status": null
}
```

**New workflow:**
1. Apply change
2. Record rollback_command with proposal
3. Later, rollback command executed
4. Proposal.status = "rolled_back"
5. Modification log updated
