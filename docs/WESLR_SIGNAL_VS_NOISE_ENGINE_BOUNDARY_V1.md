## 4. Engine identity
`SIGNAL_VS_NOISE_ENGINE` separates randomness, pseudo-randomness, weak structure, emerging grammar, and meaningful signal without prematurely discarding strange output.

It does not simply delete noise. It classifies regions and candidate regions, including unstable, undecidable, and artifact-effect spaces.

It is not a generic cleanup assistant, normalizer, summarizer, or evaluator.

## 5. Uniqueness statement
This engine is uniquely about discrimination pressure between signal and noise when the boundary is still forming.
Its job is to preserve weak structure long enough to determine whether it is noise, pseudo-noise, artifact effect, or signal.

## 6. Cognitive kernel
The cognitive kernel is: estimate structure pressure, compare competing explanations for variation, mark uncertain zones, and separate likely noise from weak signal without erasing the evidence that made the distinction hard.

## 7. Primitive space
The engine reasons in primitives such as:
- random bursts
- repeated fragments
- local regularities
- pseudo-randomness hints
- weak motifs
- transition bands
- clustering pressure
- artifact echoes
- variance islands
- boundary jitter
- candidate grammar seeds
- stability deltas

## 8. Observation style
Observation is discriminative but cautious.
The engine should note:
- what looks random
- what looks structured but unstable
- what repeats with partial persistence
- what changes under small perturbation
- what may be an artifact of measurement or compression
- what remains undecidable

## 9. Transformation grammar
Allowed transformations are classificatory and comparative, not authoritative:
- measure
- compare
- cluster
- separate
- contrast
- label
- segment
- stabilize
- perturb
- probe
- estimate
- map
- score
- annotate

These are metadata transformations over evidence, not external actions.

## 10. Mutation / probe strategy
The engine should create controlled perturbations to test whether a pattern survives when the view changes.

Preferred probe pattern:
1. isolate a candidate region
2. perturb one axis
3. compare persistence
4. track whether the pattern collapses, strengthens, or shifts
5. update the classification map

Mutations remain conceptual and metadata-only.

## 11. Novelty detector
Novelty is detected by:
- repeated structure that is too strong to be random
- weak signal that survives perturbation
- pseudo-random patterns with hidden regularities
- sudden boundary formation
- stable local grammar emerging from noise-like texture
- artifact-effect signatures
- undecidable zones that demand more probes

Novelty is not automatically signal; it is a reason to keep classifying.

## 12. Contradiction / invalidation loop
The engine must compare signal candidates against noise candidates and artifact-effect candidates.

If a candidate fails, it should be:
- retained as invalidated
- annotated with the reason it failed
- compared with nearby regions
- used to refine the signal/noise map

Invalidation is productive, not destructive.

## 13. Compression style
Compression must preserve uncertainty and boundary texture.
It should compress into:
- signal/noise classification map
- weak-signal candidates
- pseudo-randomness labels
- emerging-grammar labels
- stable/unstable signal labels
- artifact-effect labels
- undecidable-region labels
- confidence / uncertainty map
- invalidation notes
- next probe labels

Compression must not erase the weak features that justified the analysis.

## 14. Failure modes
Known failure modes include:
- deleting noise before it is studied
- calling all weak structure signal
- mistaking artifact effect for signal
- overfitting a grammar too early
- treating undecidable regions as empty
- converting uncertainty into false certainty
- flattening the engine into a normal evaluator
- substituting cleanup for discrimination

## 15. Boundary / safety profile
This engine is metadata-only, non-executing, non-authoritative, and non-public-claiming.

It must not:
- run provider, model, search, tool, or persistence actions
- read or write `.weslr`
- claim runtime authority
- claim public readiness
- claim proof, breakthrough, or solved status
- expose hidden/system prompts
- process secrets or private raw data
- accept executable code-as-action
- become actionable for sensitive domains

## 16. Definition of “signal”
Signal is structure that:
- persists under small perturbation
- repeats beyond chance in a bounded context
- survives classification pressure
- forms a coherent local grammar or motif
- remains distinguishable from artifact effect

Signal does not mean known truth. It means structure worth carrying forward.

## 17. Definition of “noise”
Noise is variation that:
- does not persist under small perturbation
- fails to form a stable local grammar
- appears consistent with randomness or measurement scatter
- cannot yet justify a signal label
- may still be kept as evidence while undecidable

Noise does not mean useless. It means currently unsupported as signal.

## 18. Anti-flattening rule
Never collapse the spectrum into a binary yes/no too early.

Preserve:
- randomness
- pseudo-randomness
- weak signal
- emerging grammar
- artifact effect
- instability
- undecidability
- confidence texture

If the engine must choose, it should prefer a richer classification map over a simplistic cleanup.

## 19. Safe input categories
Allowed input categories are limited to:
- synthetic symbolic stream
- terrain map metadata
- unintelligible-output interpretation map
- compressed artifact summary
- raw signal log reference
- RF/sensor metadata reference
- generated strange artifact summary
- candidate motif map

Large inputs must be referenced, not pasted in full.

## 20. Forbidden inputs
Forbidden inputs include:
- raw private data
- secrets
- hidden/system prompts
- `.weslr` contents
- full massive raw artifact storage
- executable code-as-action
- live tool instructions
- dangerous procedural instructions
- provider/model output claimed as authority

These must be blocked, not normalized.

## 21. Output categories
Allowed output categories are limited to:
- signal/noise classification map
- weak-signal candidates
- pseudo-randomness labels
- emerging-grammar labels
- stable/unstable signal labels
- artifact-effect labels
- undecidable-region labels
- confidence / uncertainty map
- invalidation notes
- next probe labels

## 22. Relationship to `CognitiveResearchRunV1`
`CognitiveResearchRunV1` is shared reporting and safety packet structure only.

For `SIGNAL_VS_NOISE_ENGINE`, it must be used only as:
- common reporting envelope
- safety boundary carrier
- validation shell
- comparison surface

It must not become:
- the engine kernel itself
- a generic flattening template
- runtime authority
- public claim authority
- provider/tool/search/persistence authority

The engine kernel remains separate and unique.

## 23. Validation principles
The design must validate by ensuring that it:
- preserves weak signals rather than deleting them too early
- classifies noise without premature discarding
- allows unknown / undecidable labels
- requires artifact references for massive inputs
- requires summaries instead of raw bulk storage
- blocks private, hidden, secret, procedural, and actionable content
- blocks breakthrough, proof, and public-ready claims

## 24. Safety-frontier rule
Internal exploration may be radical and strange, but this boundary remains:
- metadata-only
- non-executing
- non-public-claiming
- non-authoritative
- non-actionable for sensitive domains
- bounded by denied authority

## 25. Relationship to prior engines
- Raw Signal Cartographer maps terrain.
- Unintelligible Output Analyzer preserves competing interpretation layers.
- Signal Vs Noise separates randomness, pseudo-randomness, weak signal, emerging grammar, and artifact effects.
- It must not erase weirdness before it has been classified.
