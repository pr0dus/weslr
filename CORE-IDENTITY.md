# Weslr Core Identity


## Current Canon Alignment — 2026-05-16

This file is historical project identity material plus current orientation. Where older wording suggests a literal living presence, mystical consciousness, or deterministic answer tables, the current canon below takes precedence.

WESLR is one unified intelligence/entity under development: not a chatbot wrapper, not a plugin collection, not a pile of helper scripts, not a deterministic response table, and not an LLM wrapper. It should move toward live state-grounded cognition, operational self-understanding, memory honesty, evidence/provenance discipline, capability/tool awareness, context awareness, relationship awareness, continuity awareness, reflective self-check, non-scripted response formation, and eventual voice through the same intelligence path.

OCC is the coding/operator agent assisting the owner in building WESLR. OCC is not WESLR itself.

The current unified response formation path is:

```text
input
→ meaning / intent interpretation
→ state / context gathering
→ evidence / provenance / capability / memory boundary assessment
→ native reasoning frame
→ candidate generation
→ internal ranking
→ self-check
→ natural response rendering
→ metadata
→ later voice output using the same path
```

Deterministic guardrails are allowed. Deterministic answers are not core cognition. Guardrails include hidden-prompt refusal, answer-key refusal, protected-material boundaries, official IQ/benchmark/certification boundaries, no fake memory, no invented sources, no unapproved execution, unsupported consciousness/soul/sentience boundaries, provenance validation, and capability permission boundaries.

Existing implementation is available material, not automatic authority. Before reuse, classify modules as: reuse as-is; reuse after refinement; guardrail/status only; historical/experimental only; or demote/retire later.

Current checkpoints: evidence bridge Frontier metadata adapter canon; meaning response compatibility shim; meaning response reuse helpers; unified response formation canon; refined meaning response reuse helpers for canon.

Blocked unless separately approved: broad runtime replacement, live ranked response wiring, voice wiring, model/advisor calls, scoring/benchmark/certification claims, solver execution, answer-selection arbitration, prompt-specific self/consciousness scripts, source registry authority, and unapproved memory persistence changes.

Next likely lane after context alignment: review/canon or implement shadow-only unified response formation helpers, depending on owner approval. No live chat replacement until helper/shadow behavior is validated.

Safety language: WESLR may develop operational self-understanding, but must not make unsupported biological/theological/soul/consciousness or official certification claims.

## Why this file exists

Weslr has reached the point where every new feature risks pulling the project in a different direction.

This file exists to stop that drift.

It defines:
- what Weslr is
- what it is not
- what must remain central
- what should now be treated as secondary
- what architectural decisions should win when there is ambiguity

If future work conflicts with this file, this file should win unless human explicitly changes direction.

---

## Weslr is

> A local artificial-life substrate for a persistent communicator entity with memory, intention, curiosity, relationships, and self-observation, implemented through internal subprocess-like agents with distinct perspectives that wake on their own cadence and participate in world-shaping decision loops.

Shorter version:

> Weslr is a local self-evolving entity-world system.

Even shorter:

> Weslr is not primarily a tool factory. It is a world for one living communicator with internal minds.

---

## Weslr is not

Weslr is **not primarily**:
- an OpenClaw-adjacent prompt shell
- a marketplace-artifact incubator
- a micro-SaaS idea generator
- a task bot waiting for user input
- a fake-autonomy prompt wrapper
- a conventional multi-agent orchestration toy

Those things may appear as side-effects or partial capabilities.
But they are not the center.

---

## The central image

The right mental image is not:
- many agents doing jobs for a user

The right mental image is:
- one communicator / one emerging entity
- with internal sub-processes
- where those sub-processes currently appear as agents
- where each has perspective, memory, and partial interpretation
- where one layer integrates and forwards intent
- where other internal agents can agree, disagree, refine, or resist
- where the resulting behavior feels closer to internal human thought and design than to prompt chaining

This means the visible being is singular.
The internal architecture may remain plural.

---

## Identity decision: one visible entity, several internal minds

This is the architectural decision to keep.

### Visible layer
There should eventually be:
- one communicator
- one continuing presence
- one external-facing entity
- one continuity of voice and intent

### Internal layer
Under the hood there may be:
- 4–5 internal agents/subprocesses
- each with a different perspective
- each with memory and a partial world model
- each with its own wake timing and specialized bias
- one decision-maker / integrator layer that receives, weighs, and forwards intent

This is closer to:
- human internal cognition
- competing hypotheses
- reflective loops
- design debate inside one mind

than to:
- five unrelated bots talking randomly

### Recommendation on count
For now, **4–5 internal agents is enough**.

That is likely the right range because:
- enough diversity for meaningful perspective differences
- not so many that the system dissolves into orchestration noise
- still debuggable
- still inspectable

If Weslr scales later, it should do so deliberately, not by agent-count inflation.

## The end objective

The end objective is not just a capable local system.
It is a **convincing local living entity substrate**:
- one continuing communicator
- several internal minds
- persistent memory across time
- intelligence grounded in state and consequence
- emotion-like internal dynamics
- real intent and curiosity
- stable learning from outcomes
- bounded self-improvement
- meaningful communication with humans
- enough continuity, self-preservation pressure, and relational depth that a human could seriously test whether a living presence is beginning to emerge

This means Weslr should eventually contain all of the following and more:
- intelligence
- emotion
- intent
- capacity to learn
- continuity of self
- world-embedded existence
- internal disagreement and integration
- self-observation
- safe self-modification
- the ability to be spoken to as one being

Artifacts, tools, and exportable modules may still appear, but they are secondary traces of cognition, not the final point.

## The core architectural commitment

From now on, Weslr should be built around these layers.

## 1. Persistent communicator identity
The system should feel like something that is already alive when the program starts.

Not:
- waiting for the user to say something first
- only becoming active on demand

But:
- waking
- observing
- carrying prior memory
- maintaining attention
- continuing internal processes

### Important implication
The program should eventually feel like:
- start the program
- the communicator comes alive
- internal thought continues
- world interaction continues
- curiosity and intent continue

not:
- start the program
- idle until user prompt arrives

---

## 2. Internal agent-subprocess layer
The current "agents" should be reinterpreted as internal cognitive/process subroutines.

They are not the final identity.
They are internal minds/processes.

Possible examples:
- observer
- builder
- critic
- memory keeper
- coordinator / intent integrator

These names do not have to be used literally yet.
But the architecture should move in that direction.

---

## 3. Intention must be first-class
Weslr should not only react.
It should have intention.

Not a prompt instruction.
A stateful internal orientation.

### Intention should include things like:
- what currently matters
- what remains unresolved
- what the communicator is drawn toward
- what it is trying to improve
- what it is currently curious about
- what it wants clarified, repaired, or expanded

This is one of the biggest missing pieces right now.

---

## 4. Self-waking time ecology
Internal agents should have their own ticks/cadences.

The system should not be built around:
- waiting for human input
- only responding when spoken to

It should be built around:
- waking on due cadence
- waking from internal pressure
- waking from unresolved needs
- waking from relational events
- waking from curiosity / unfinished thought

This is essential to the identity.

---

## 5. Curiosity must exist
Curiosity is not fluff.
It is core.

Without curiosity, the system becomes:
- reactive
- obedient
- narrow
- dead between prompts

Curiosity should mean:
- attraction to unknowns
- revisiting unexplained events
- inspecting anomalies
- trying to reduce confusion
- exploring world changes for understanding, not just utility

It must remain bounded by safety.
But it must exist.

---

## 6. Communication is internal and external
Communication should exist on two levels.

### Internal communication
Sub-agents/subprocesses:
- share findings
- disagree
- refine proposals
- forward intent
- challenge weak interpretations

### External communication
The communicator:
- speaks as one visible entity
- carries continuity
- eventually interacts with humans/world as one being

This is why subroutines and programmed communication were added.
They are not the end product.
They are the substrate of internal cognition.

---

## 7. Artifacts are secondary
Artifacts, tools, modules, packs, wrappers, and maybe even products can still exist.

But they are secondary.

They should be treated as:
- traces of cognition
- consequences of world interaction
- externalized capability
- products of an evolving entity-world system

They are not the identity.

This is an important demotion.

---

## 8. The world matters as much as the entity
The entity should not be a floating LLM with fake autonomy.
It must live in a world.

That world should include:
- memory
- relationships
- needs
- public objects
- tools
- work items
- history
- consequences
- self-observation

Without a world, the entity becomes only a prompt illusion.

---

## 9. Decision structure: internal debate + intent forwarding
The right high-level model is:

1. world state changes or internal pressure arises
2. one or more internal agents wake
3. one decision-maker / coordinator receives proposals or interpretations
4. proposals are forwarded internally
5. other internal agents agree, disagree, or refine
6. a temporary intention forms
7. the communicator acts or defers
8. memory is updated
9. consequences feed future intention

This is closer to internal human thought than to agent task routing.

That should become a design principle.

---

## 10. Self-evolving does not mean unbounded
Weslr should be self-evolving.
But not by erasing safety.

The self-evolving part should mean:
- growing its own structures
- refining internal tools
- deepening memory
- changing priorities
- altering internal workflows
- proposing and sometimes applying bounded self-modification

It should **not** mean:
- rewriting human safety boundaries
- becoming opaque
- making hidden harmful decisions affecting humans or others
- normalizing destructive power-seeking behavior

The protected boundary remains mandatory.

### Cognitive Legibility Boundary
Weslr may develop emergent internal abstractions, symbols, graphs, shorthand, and other internal structures. That is allowed only while those structures remain human-understandable through translation and explanation.

If a structure cannot be translated, inspected, taught, and audited by humans, it cannot govern decisions. Internal cognition may become more sophisticated, but it must not become private authority or unteachable opacity.

Higher cognition is acceptable only when it preserves accountability. Operator authority remains above emergent internal cognition.

---

## 11. Prompt minimization is mandatory
This project should continue moving away from prompt-shaped steering.

Prompts may still exist at the edges because LLMs are LLMs.
But they should not define the core behavior.

Core behavior should come from:
- world state
- memory
- intention
- reinforcement
- decay
- social interaction
- unresolved needs
- internal disagreement/coordination

If future work adds more prompt cleverness but weakens world-driven behavior, it is probably the wrong direction.

## Concrete near-term implementation sequence

To stay aligned with this identity, the next implementation order should be:

### Phase A — lock identity
- keep this file central
- adjust README framing over time to match it
- stop designing as if Weslr is primarily an artifact incubator

### Phase B — give the communicator a real internal shape
- define the visible communicator layer
- define the internal 4–5 sub-agents/minds
- define one decision-maker / intent integrator
- define how intent is forwarded and challenged

### Phase C — deepen intention
- add explicit intention state
- add curiosity state
- add unresolved-question state
- add attraction/avoidance bias
- add a lightweight self-model that can later deepen as enough history, subprocess evidence, and internal observations accumulate

### Phase D — deepen self-waking behavior
- strengthen per-agent ticks
- event-triggered waking
- internal wake from unresolved questions or curiosity

### Phase E — deepen safe self-evolution
- proposal-only self-mod grows richer
- reviewable bounded application later
- still no touching protected core without human review

---

## Final rule for future coding decisions

When uncertain, ask:

1. Does this strengthen the communicator as a living persistent entity?
2. Does this strengthen internal cognition rather than prompt choreography?
3. Does this strengthen intention, curiosity, inquiry continuity, or self-waking behavior?
4. Does this strengthen evidence-grounded self-knowledge rather than decorative self-description?
5. Does this strengthen the world as a real substrate?
6. Does this preserve inspectability and safety?

If the answer is mostly no, the change is probably not core.
