## /chat Internal Routing Fix

**Problem:** `"What time is it?"` and similar system questions always fell through to `_get_language_module().simple_response()` → "I'm here. Say something simple..."

**Root cause:** Two-phase routing issue:
1. `"what time is it"` → `likely_need = "question"` → `direct_answer` branch → no match → `simple_response()`
2. `"what is your system status"` → `likely_need = "concept_explanation"` → never reaches `direct_answer` → goes to concept synthesis → generic response

**Fix applied to `dialogue.py`:**

Added internal fact routing in TWO places:

### 1. `direct_answer` branch (line ~700)
Handles `"what time is it"`, `"what can you do"`, `"are you healthy"`, `"system status"` when `likely_need = "question"`.

### 2. `concept_explanation` branch (line ~775)
Added `internal_routed` flag to intercept system questions BEFORE concept synthesis.
Handles same patterns when `likely_need = "concept_explanation"`.

**Routed patterns:**
- `time_patterns`: "what time is it", "what's the time", etc. → real clock via `datetime`
- `status_patterns`: "system status", "your status", "how are you doing" → `load_failsafe_status()` + `load_llm_status()`
- `health_patterns`: "are you healthy", "are you ok", "are you working" → `load_failsafe_status()`
- `capability_patterns`: "what can you do", "what are your capabilities" → hardcoded capability list

**Test results after fix (server running on ports 8001/8778):**
- `what time is it` → ✅ `"It is 22:03 local time (Europe/Berlin). UTC is 20:03."`
- `what is your system status` → ✅ `"I am initialized. LLM provider: ollama."`
- `are you healthy` → ✅ `"Running in SAFE mode. All systems operational."`
- `what can you do` → ✅ `"I can track time, maintain session context..."`
- `hello there` → ✅ `"I'm here. Say something simple..."` (unchanged)

## Ollama Wiring Fix — 2026-04-19 00:10

**Problem:** provider_available=false in /api/health even though Ollama was running and provider_config.json had provider=ollama.

**Root cause:** main.py:2280 `from llm_runtime import get_provider` — but `get_provider` is in `weslr.providers`, not `llm_runtime`. The import always failed silently, so provider_ok was always False.

**Fix:** Changed to `from weslr.providers import get_provider as _get_provider`.

**Also required:** Start server with `WESLR_LLM_PROVIDER=ollama WESLR_LLM_MODEL=qwen2.5:0.5b-instruct python main.py serve --port 8001`. Without this, config.py defaults win (WESLR_LLM_PROVIDER=embedded, model=gguf filename not an Ollama model name).

**Result after fix:**
- provider_available: true ✅
- time routing: "It is 00:20 local time (Europe/Berlin). UTC is 22:20." ✅
- regression tests: 9/9 PASS ✅

**Remaining issue:** "say exactly one word" still returns simple_response (not LLM). Likely because lead_topic='say' is checked against simple word list in direct_answer branch. Turn type 'statement' with no topics → direct_answer → simple word check → no match → fall through to simple_response().
