```
chat request
  → build_communicator_message_payload (dialogue.py)
    → _response_signals._quality_class computed
    → _truth_guard computed
  → main.py HTTP handler
    → interpret_human_turn → lneed
    → _check_quality_watch → qnote (fires at count>=3)
    → _detect_confusion → cstate (confusion_signal + confusion_type)
    → _derive_adaptive_hint → hint (if cstate[confusion_signal])
      → simplification_request: _generate_simpler_reanswer → append to message
      → explicit_clarification: metadata hint only
      → expectation_gap: metadata hint only
    → _derive_governance_candidate → candidate
    → _derive_improvement_recommendation → recommendation
    → chat.message event logged (with quality_class, quality_note, _governance_observation)
    → governance.observation event logged (if qnote present, with candidate + recommendation)
    → confusion.signal event logged (if cstate[confusion_signal])
    → adaptive.hint event logged (if hint derived)
  → response returned with _quality_class, _confusion_state, _adaptive_hint, _quality_note
```

### Architecture Decisions This Session

1. **`_WATCH_HISTORY` as in-memory rolling list** — bounded (max 10), no persistence needed, same pattern as `_MEMO_HISTORY` will be
2. **`global` statement error** — Python requires the name to already be referenced in the function body before the `global` declaration. Removed `global _WATCH_HISTORY` inside `do_GET` (caused SyntaxError)
3. **Confusion detection before quality watch in handler** — order matters; confusion uses message directly, quality uses interpreted need
4. **`auto_apply=False` invariant** — all governance candidates and recommendations always have `auto_apply=False`. Operator must approve any action
5. **Simplification auto-adaptation only fires for `simplification_request`** — explicit_clarification and expectation_gap get metadata hint only (safer)
6. **`_generate_simpler_reanswer` bounded to one sentence** — first period truncation prevents long double-answers

### Bug: dialogue.py `has_research_answer` (Critical, No Commit)
- **Problem:** "What is 2 + 2?" via `/chat` returned HTTP 500: `cannot access local variable 'has_research_answer' where it is not associated with a value`
- **Root cause:** `dialogue.py:975` — `has_research_answer` assigned inside `if synthesis: ... else: ...` block, but used again at line 976 outside that block. When `synthesis` is falsy, the `else` block runs and assigns it. But Python sees the reference at line 976 as potentially unbound if the outer `if/else` doesn't cover it — actually, the real issue was the structure: `if synthesis: message = synthesis else: has_research_answer = bool(...)` then `if has_research_answer:` — Python treats the assignment in the `else` branch as not guaranteeing the variable is set when the `if synthesis` branch is taken (synthesis could be truthy, skipping both branches)
